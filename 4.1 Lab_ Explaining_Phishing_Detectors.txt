1. What is this lab about? 
When a security detector says “this URL is phishing”, the analyst needs to know why 
before blocking the site or 
warning the users. In this lab you work on one problem: is this web address (URL) a phishing site? 

• Part A: build the detectors in the three ways you met in Labs 1 to 3: supervised (every URL has a label), semi-
supervised (only 5% have a label, the model also learns from the other 95%) and self-supervised (the model 
first learns from the URLs alone, then uses the 5% labels). 
• Part B: explain them with the models themselves (glass boxes), SHAP and LIME. 
• Part C: test how much the detector needs outside lookups, and how stable LIME is. 
• Part D: turn the explanation into rules: build a small Belief Rule-Based expert system (BRB) from the two 
most important features, like in the BRB slides and lab 3.

3. The ideas, explained simply 
The examples use made up numbers; your own numbers will be different. In this lab, always report macro-F1, 
recall and FAR. 

3.1 Lower lines and the self-supervised game 
Lower line. If the semi-supervised model scores 0.93, is that good? You only know after you train the same model 
on the 5% labels alone. That score is the lower line: the unlabelled data only helped if you beat it. 
Self-supervised game. We hide some clues of each URL and a network must guess them back, e.g. nb_dots = 5, 
nb_hyphens = 4, length_url = ?. To win, it learns how clues go together, without anyone telling it what 
phishing is. 

3.2 Glass box, black box, global, local 
A glass box (a small tree, a logistic regression) can be read directly. A black box (a forest of 300 trees, a neural 
network) is too big to read, so we explain it from outside with SHAP and LIME. A global explanation says what the 
model looks at in general; a local one says why one URL got its score. 

3.3 SHAP: “sharing the prize fairly” 
SHAP starts from the base value (the average score of ordinary URLs) and says how much each feature pushed this 
URL's score up or down. The pushes always add up exactly to the model's score: 
Made-up example: one URL scored 0.92 phishing 

0.50 (base) + 0.25 (domain_age, very new) + 0.12 (phish_hints) + 0.08 (nb_hyphens) + 0.03 (page_rank) 
− 0.06 (length_url, short) = 0.92 
A waterfall plot shows this for one URL. A bar plot shows the average push of each feature, and a beeswarm 
shows one dot per URL (red = high value, right = toward phishing). For forests, shap.TreeExplainer is exact and 
fast; for other models, shap.Explainer works too. 


3.4 LIME: “draw a straight line nearby” 
LIME makes thousands of small changes of one URL, asks the model to score them, and fits a straight line through 
the answers. It shows each feature as a range: page_rank <= 1.00 +0.16 means this low page_rank pushes 
the score 0.16 toward phishing. Its fit score (0 to 1) says how well the line copies the model: below 0.5, do not 
trust it much. LIME is random, so another seed can give another answer: it may not be stable. You test this in Part 
C. 

3.5 The trade-off 
The more accurate model (maybe the forest) is usually harder to read, the easy-to-read model (the tree) may miss 
more attacks, and fewer labels save money but may cost accuracy. Your job is not to find the “best” model but to 
measure these things and argue which balance fits a real security team. If a simple model is almost as good, or the 
unlabelled data does not help, that is an interesting finding: write it down. 

3.6 The BRB, one more time 
Two antecedents (your two top features), each with three referential values Low / Medium / High, give 3 × 3 =9 
belief rules, e.g. IF page_rank is Low AND nb_hyperlinks is Low THEN risk is {Low 0.00, Medium 0.11, High 0.89}. 
Evidential Reasoning combines the active rules; when they disagree, part of the belief becomes Unknown. The 
utility (Low 0, Medium 0.5, High 1) turns the beliefs into one phishing score.

Step A3: A helper to score any model 

Macro-F1, recall, ROC-AUC and FAR 

from sklearn.metrics import (f1_score, recall_score, roc_auc_score, 
confusion_matrix) 

def report(model, X, y): 

"""The four numbers we use for every model in this lab (3 decimals).""" 

pred = model.predict(X) 

prob = model.predict_proba(X)[:, 1] 

tn, fp, fn, tp = confusion_matrix(y, pred).ravel() 

scores = { 

"macro_F1": f1_score(y, pred, average="macro"), 

"recall": recall_score(y, pred), # share of phishing we caught 

"ROC_AUC": roc_auc_score(y, prob), 

"FAR": fp / (fp + tn), # share of legit wrongly flagged 

} 

return {k: round(float(v), 3) for k, v in scores.items()}

Step A8: Pseudo-labelling 

As in Lab 2: the forest guesses the unlabelled URLs, keeps only the guesses it is very sure about (CUTOFF = 0.9; you 
can try 0.85 or 0.95), and adds them as if they were labels. Three rounds, then the final model. 

# Semi-supervised: pseudo-labelling (the same idea as Lab 2) 
X_now, y_now = X_lab.copy(), y_lab.copy() # starts with the 5% real labels 
pool = X_unlab.copy() # URLs without a label 
rf_semi = RandomForestClassifier(n_estimators=300, random_state=42, n_jobs=-1) 
CUTOFF = 0.9 # try 0.85 or 0.95 too 

for rnd in [1, 2, 3]: 
rf_semi.fit(X_now, y_now) 
p = rf_semi.predict_proba(pool)[:, 1] 
sure = (p >= CUTOFF) | (1 -p >= CUTOFF) # sure phishing OR sure legit 
guess = pd.Series((p[sure] >= 0.5).astype(int), index=pool.index[sure]) 
X_now = pd.concat([X_now, pool[sure]]) # add them as labels 
y_now = pd.concat([y_now, guess]) 
pool = pool[~sure] 
print(f"round {rnd}: added {sure.sum()} guesses,", 

f"{len(pool)} still unlabelled") 

rf_semi.fit(X_now, y_now) # final model: labels + guesses 
print("semi-supervised:", report(rf_semi, X_val, y_val)) 

What you should see 

How many guesses each round added, then the scores. Do not be surprised if it is NOT better than the forest 
with 5% labels: on this dataset a forest is already strong with few labels. That is a real result: say so in your

5.3 Self-supervised: learn from the URLs alone first 
Step A9: A fill-in-the-blanks network, then 5% labels 

we hide 20% of the (scaled) values and train a small network to give back the complete row, without labels. Its 
middle layer has 32 numbers per URL. A logistic regression then uses those 32 numbers and the 5% labels. The 
Pipeline makes the whole thing work like any other model. 

# Self-supervised: learn from the URLs alone, no labels (like Lab 3) 
from sklearn.neural_network import MLPRegressor 
from sklearn.preprocessing import FunctionTransformer 

scaler = StandardScaler().fit(X_train) # uses no labels 
Z = scaler.transform(X_train) 

# The made-up task: hide 20% of the clues and ask the network to fill them in 
rng = np.random.default_rng(42) 
hidden_part = rng.random(Z.shape) < 0.2 
Z_masked = np.where(hidden_part, 0.0, Z) # 0 = average value after scaling 

ae = MLPRegressor(hidden_layer_sizes=(32,), max_iter=300, random_state=42) 
ae.fit(Z_masked, Z) # input: with holes, target: complete 
print("fill-in error:", round(ae.loss_, 3)) 

def encode(X): 
"""The 32 numbers the network learned for each URL (its middle layer).""" 
h = scaler.transform(X) @ ae.coefs_[0] + ae.intercepts_[0] 
return np.maximum(h, 0) # same "relu" as inside the network 


# Now use the 5% labels, but on the 32 learned numbers 

self_sup = Pipeline([ 
("encode", FunctionTransformer(encode)), 
("lr", LogisticRegression(max_iter=1000)), 

]) 

self_sup.fit(X_lab, y_lab) 

print("self-supervised:", report(self_sup, X_val, y_val)) 

What you should see 

The fill-in error (it only tells you the game was learned) and the scores. The fair comparison is logistic regression 
with 5% labels (step A7).

Step D2: The BRB code (example) 

Step 1 splits a value between its two nearest reference values. Step 2 finds how strongly each of the 9 rules 
matches. Step 3 combines the rules with real Evidential Reasoning, so the output also has an Unknown part. 

# Step 1: input transformation (same as in the BRB slides) 

def transform_to_belief(value, references): 
value = float(value) 
n = len(references) 
belief = [0.0] * n 
if value <= references[0]: 

belief[0] = 1.0 
return belief 

if value >= references[-1]: 
belief[-1] = 1.0 
return belief 

for i in range(n -1):

# Step 3: Evidential Reasoning (ER) 
def combine_two(b1, ig1, b2, ig2, n=3): 
conflict = sum(b1[i] * b2[j] for i in range(n) 

for j in range(n) if i != j) 
k = 1 / (1 -conflict) 
new_b = [k * (b1[i] * b2[i] + b1[i] * ig2 + ig1 * b2[i]) 

for i in range(n)] 
return new_b, k * (ig1 * ig2) 

def er_aggregation(weights, rules, n=3): 
act = [(w, r) for w, r in zip(weights, rules) if w > 0] 
bel = [[w * v for v in r] for w, r in act] 
ign = [1 -sum(b) for b in bel] 
fb, fg = bel[0], ign[0] 


for i in range(1, len(bel)): 
fb, fg = combine_two(fb, fg, bel[i], ign[i], n) 
return fb, fg 
fb, fg = combine_two(fb, fg, bel[i], ign[i], n) 
return fb, fg 

def brbes_inference(v1, v2): 
belief1 = transform_to_belief(v1, refs1) 
belief2 = transform_to_belief(v2, refs2) 
aw = calculate_activation_weights(belief1, belief2) 
final_belief, ignorance = er_aggregation(aw, rules) 
return belief1, belief2, aw, final_belief, ignorance
